# 任务 B 选型判断：哪个项目最好 + "要不要上蘑菇体"

> 日期：2026-10-06
> 用户问题：① 目前哪个项目最好？② 后续要扩展，是不是越完整越好？③ 蘑菇体学习说不定有用？
> 本文是判断，不是选项清单。结论放最前。

---

## 0. 结论（三句话）

1. **选 `suifei/flywire-fly-lab`。不是接近的胜负，是压倒性的。**
   它不是"又一个候选"，它是**其它候选的超集** —— 同一套 Shiu/Eon 方程，外加实时引擎、子回路提取管线、
   刺激编码、读出、可塑性模块。其它项目都是它的真子集。
2. **不要在 v3 / v5 之间二选一 —— 这是个假两难。**
   它的子回路是**脚本生成、逐层嵌套**的（v3⊂v4⊂v5）。"扩展"= 用它的管线按我们的传感器重跑一遍，
   **不是去改它的代码**。所以"复杂、要大量调整"这个担心不成立。
3. **蘑菇体（MB）现在不上。** 四条硬理由（见 §5），核心是：**它是嗅觉回路，而我们的板子没有嗅觉传感器**；
   而且它的记忆在模型里**走不到马达**。但**门要留着**（§5.1）—— 加一个气味传感器它就能用。

## 2. 决定性事实：子回路是"脚本生成、逐层嵌套"的

这不是推测，是读源码读出来的：

- **`dodge/subcircuit.py` 是参数化的**：
  ```python
  def __init__(self, ..., wmin, K):
      INPUTS  = [("LC4",...), ("LPLC2",...)]     # 输入种子组
      TARGETS = [DNp01, DNa01/02, ...]           # 输出目标组
      # 选中/输出起，BFS 跳数 dS+dT ≤ K 的全部神经元 + 它们之间的全部连接
  ```
  换句话说：**给一组"输入 + 输出"，它自动裁出一条子回路，导成一个 JSON。**

- **`dodge/subcircuit_v5.py` 的文档字符串明写**：
  > "子回路 v5 = 子回路 v4（6,296 个，**原样**）＋ 蘑菇体……前 6,296 个神经元的编号、分组、
  > 它们之间的连接与 v4 **逐位相同**"

  ⇒ **v5 ⊃ v4 ⊃ v3 ⊃ v2 ⊃ v1，且新版本是"旧版原样 + 新模块"。**

**推论**：所谓"扩展这个项目"，在我们这里 = **用它的管线生成我们自己的一份子回路**。
改代码的工作量 ≈ 0。这就是为什么"项目太复杂、要大量调整"的担心**在我们这条路上不成立**。

## 3. "越完整越好"是个陷阱 —— 但要按"能装上的传感器"来算

> ⚠️ **本节已于 2026-10-06 更正。** 前一版说"没有摄像头、没有光敏"—— 那是只看了**板载器件**。
> 实际上 **ESP-Mosaico 有两个扩展槽（subboard）**，视觉与光敏都是**官方扩展模块**。
> 正确说法是"**还没插**"，不是"**用不了**"。

**板载 + 扩展槽的完整传感器清单**：

| 来源 | 器件 | 对应脑通道 |
|---|---|---|
| 板载 | 麦克风 ES8311 | **JO**（听觉/风感） |
| 板载 | IMU BMI270 | 本体感觉 → **TOUCH** 强度调制 |
| 板载 | 磁力计 BMM150×2、触摸 CST9220 | 磁吸 / 接触 |
| 板载 | 480×480 屏、振动马达 | **输出** |
| **扩展槽** | **相机模块 `mosaico_module_camera`**（OV3640/SC101IOT，**仅左槽**） | **LC4 / LPLC2 / LC16**（视觉 looming） |
| **扩展槽** | **互动模块 `mosaico_module_interact`**（触/键、运动、**光**、WS2812、红外） | **光感 / 触摸 / 红外** |
| 扩展槽 | 摇杆模块、双键+WS2812 模块 | 游戏输入 |
| **仍然没有** | 气味、味觉、温度、湿度 | ORN/OLFA、SUGAR/BITTER、THERMO/HYGRO |

**结论修正**：v3/v5 里我们"喂不了"的，现在只剩 **嗅觉 / 味觉 / 温湿**；
**视觉（LC4/LPLC2/LC16）可由左槽相机驱动，光敏可由互动模块驱动。**

⚠️ 两条必须知道的**硬约束**（BSP README + 作者实测）：

1. **相机只在左槽，且与 USB Serial/JTAG 引脚冲突** ⇒ 装相机后必须**走 UART 刷写/看日志**。
   这对我们现在的 ESP-Iris(USB) 流程是**实打实的影响**，方案里要预留。
2. **视觉不是"接上就灵"**：作者实测**从光感受器(R1-6/R7/R8)驱动 → 下行神经元全 0 Hz**，
   必须注入到 **LC4** 这类投射神经元；且"真实像素 → flyvis → LPLC2"这条链在 **45 mm 外读数恒为 0**，
   25 mm 内才分得出来。⇒ 视觉可用，但要按它这两条负结果来设计（注入点、有效距离）。

再看两个子回路需要喂什么（更正后）：

| 子回路 | 它围绕什么建的 | 我们现在能喂的 | **仍喂不了的** |
|---|---|---|---|
| v3（球场/躲避） | 视觉 looming → 逃跑 | JO、TOUCH、**（相机）LC4/LPLC2/LC16** | SUGAR/BITTER、THERMO/HYGRO |
| v5（生活） | v4 + 嗅觉 → 蘑菇体 | 上面全部 + 光感 | **ORN/OLFA（嗅觉 2,000+）** |

**注意**：装上相机 ≠ 应该装。视觉回路很重（LC 系列是 v3 的主体），
而我们**已经有麦克风走 JO**。所以**相机是"可选加强"，不是"默认必上"** ——
这正好对应你说的"其他传感器后期直接配"：**接口已经在，接不接是策略问题，不是可行性问题。**

**对我们真正完整的定义**是：`JO`（听/风）+ `TOUCH`（触）+ `IMU`（本体感觉调制）
→ `DNp01`（逃逸）/`DNa01`、`DNa02`（转向）/`MDN`（后退）/`MN9`（取食）/`aDN1`（梳理）。
**相机装上后，再把 `LC4/LPLC2/LC16` 折进来。**

> 注：JO = Johnston's organ（触角听觉/风感），是果蝇**唯一**能对上我们麦克风的天然通道；
> 触角机械感觉→aDN1 这条通路作者已在 §24 实测过。**我们的输入通道在生物学上是站得住的。**

## 4. 关于"扩展"的正确理解

| 你以为的扩展 | 实际上的扩展 |
|---|---|
| 改它的代码、加功能、适配我们的传感器 | **用它的管线（`subcircuit.py` + `mb_circuit`）重新生成一份子回路 JSON** |
| 复杂、要做很多调整 | 改 4 个字段（INPUTS / TARGETS / wmin / K），跑一个脚本 |
| 越完整越省事 | 越完整越浪费（喂不到的回路白算） |

**这就是为什么 flywire-fly-lab 是"最好"的深层原因**：它不是"功能最多的成品"，
它是**一个可按需重切的研究工具链**。我们买的是那把刀，不是那块最大的肉。

## 5. 蘑菇体学习：现在不上（四条硬理由）

我在服务器上读了它的学习台账（`docs/log/report.md` §11、§48）。结论是**不上，四条理由都硬**：

1. **输入是嗅觉，我们没鼻子。** MB 的输入是 `ORN`（嗅觉感受神经元 2,279 个）。
   我们的板子**没有气味传感器**。硬喂 68 字节音频进去，是纯臆造，没有生物学依据。
2. **它的输出在模型里走不到马达。** §48.4 实测：有运动落点的四类 MBON（MBON12/26/27/35）
   **一个脉冲都没有** —— 它们收到的 APL 抑制是 KC 兴奋的 **2–7 倍**。
   "记忆形成了，但走不到我们接了身体的那五个下行神经元。" 作者写了"**不再改模型去凑行为**"。
   ⇒ **就算喂对了输入，现在也出不来动作。**
3. **奖赏信号是手接的一根线。** §11.1：真喂糖，PAM 多巴胺 **0/307 放电**。
   要用 MB，必须外部直接驱动 PAM/PPL1（等价于光遗传"作弊"）。我们的机器人没有"吃到糖"这个事件。
4. **它吃掉全部余量。** MB 带来 **+8,759 个神经元（仅 KC 就 5,177）+ 33.9 万条边**
   （v4 475,562 → v5 814,649 条边）。实时倍数 **2.82× → 0.96×**，一脚踩到实时线下。

### 5.1 但门要留着（什么时候它才值得）

- **它的科学是真的**：KC→MBON 的多巴胺门控可塑性（Hige 2015）已实现并验证，
  条件化后**隔室分工与解剖一致**（PPL1 压低 MBON11 等 13 个、PAM 压低 MBON01 等 17 个，两组重合 **0.00**）。
  卡的只是"读出那道闸门"。
- **可塑性模块已经写好了**（`plasticity.js`，JS/Python 有逐位一致性检验），随时可调用。
- **它变成可用的那一天** = 我们给机器人**加一个气味传感器**（廉价 MOX 气敏元件即可）。
  那时 MB 就能直接接上，这会是很好的第三期功能。
- **另一个可能**：找一条**听觉→MB** 或**触觉→联想**的路径。目前 MB 基本只收嗅觉输入，
  这条大概率走不通 —— 除非后续调研证实存在，否则不要指望。

## 6. 推荐路线（两阶段、同一套代码）

**阶段 1（现在）—— 打通最小闭环，先不碰嗅觉/视觉**
- 用 `subcircuit.py` 生成定制子回路 **vS**：`INPUTS={JO, TOUCH}`，`TARGETS={DNp01, DNa01, DNa02, MDN, MN9, aDN1}`，
  `wmin/K` 从 v3 的参数起步。
- 预期规模 **≤ v3**（5,563 神经元 / 432,437 边）⇒ 实时余量 **≥ 3×**。
- 用服务器上**回放的 UDP 数据**（任务 A 已有的 68 字节帧）跑通：
  `68 B 特征 → JO/TOUCH 刺激 → 读出 DN → 打包下行指令`。**先不接板子。**
- 若 JO/TOUCH 对读出推动太弱（这是唯一风险），再调 `wmin/K` 或把 `AUDIO`(v5 的 370 个) 单独摘进来当第二条听觉通道。

**阶段 2（以后，按需）**
- 加了摄像头 → 把 LC4/LPLC2/LC16 折进 vS 重生成。
- 加了气味传感器 → 套 `subcircuit_v5.py` 的 MB 扩展，在 vS 上长出蘑菇体。
- **不预先背 v5 的死重。**

## 7. 待拍板的一件事

**同意"用它的管线按我们传感器定制子回路 vS"，还是先用 v3 原样（只喂 JO/TOUCH）打样？**

- 我倾向 **后者先打样**：零修改、电路已被作者验证、3.1× 余量，最快见到闭环是否成立。
- 定制的 vS 留作"打样通过后、要更多余量或要折叠新传感器"时的下一步。

> 两个方案都不改它的代码，都保留随时扩到 v5 的能力。差别只是：先证明闭环，还是一步到位把电路切干净。
