# 回答两个问题：① 上蘑菇体会不会"重新出位"？② 多通道信息叠加怎么处理？

> 日期：2026-10-06 · 承接 `STAGE1-SENSOR-TO-BRAIN-DESIGN.md`、`PROJECT-CHOICE-DECISION.md`
> 用户问：① "我后面要蘑菇体的话，不是又要重新出位吗？" ② "有很多条通道，但肯定会有信息叠加，从正常生物学反应来看，这个地方需要考虑一下如何处理。"
> 本文是判断 + 实测证据，不是选项清单。**两个结论都已在真机上验证过。**

---

## 0. 结论（两句话）

1. **上蘑菇体不会"重新出位"。** `v5 = v4（前 6,296 个，编号/分组/内部连接逐位相同）+ 蘑菇体接在后面`，
   这是仓库源码里写死并**用 assert 强制保证**的。前提是：端口按**组名**绑定（本仓库已这么做）。
2. **叠加就是对的，不需要硬仲裁。** 实测 4 种策略：优先级加权叠加（`sum`）死区 **0%**，
   还**同时**保住逃逸 100%；而分时复用把逃逸整段丢光（**0%**）。
   ⇒ 默认改成 **加权叠加**；原设计文档"必须 winner-take-all"的说法**已更正**。
   （**转向列已不再有区分力** —— 方向改由 IMU 侧向加速度直接给，见 STAGE1 文档 §0.5。）
3. **死区看门狗已实现并实测**：二维网格 9 个死区格 **9/9 被救活**。
   关键坑：**必须"压制别的通道"，光放大自己无效** —— 死区的成因是跨通道交叉抑制。
   详见 §2.4。

## 1. 问题一：蘑菇体会不会"重新出位"？

### 1.1 不会 —— 源码级证据

`dodge/subcircuit_v5.py` 的文档字符串（本轮在服务器上直接读的原文）：

> 子回路 v5 = 子回路 v4（6,296 个，**原样**）＋ 蘑菇体……**和 v4 的关系：前 6,296 个神经元的
> 编号、分组、它们之间的连接与 v4 逐位相同；蘑菇体的神经元接在后面。**

代码里也确实是这么排的：

```python
in4 = np.zeros(len(fids), bool); in4[v4i] = True
rest = [g for g in c.sel if not in4[g]]
order = np.concatenate([v4i, np.array(rest, int)])   # ← v4 强制在前，蘑菇体追加在后
...
groups = dict(v4["groups"])                          # ← v4 的组名原样继承
```

而且它自带一条**断言**，v4 内部的边若变了会直接崩：

```python
assert diff is not None and all(x[0] in alln4 for x in diff), "v4 内部的边变了（ALLN 之外）"
```

⇒ **v4 的 6,296 个神经元在 v5 里的下标 0…6295 完全不变，组名也完全不变。**
加蘑菇体是"**末尾追加**"，不是"重排"。所以**不存在"重新出位"**。

### 1.2 但有一个前提 —— 而我们已经满足了它

上面这条保证只对**官方 v4 → v5 路径**成立。将来若我们用 `subcircuit.py` 换一组
`INPUTS/TARGETS/wmin/K` **重剪**一条自定义子回路（vS），BFS 顺序会变，
**那时下标才会重排** —— 这才是唯一会"重新出位"的场景。

**一劳永逸的做法：端口按「组名 + FlyWire root ID」寻址，绝不硬编码下标。**
本轮已经把这条落到代码里：`tests/brain_b/b_loop/stage1_loop.js` 的端口表就是纯组名：

```js
const IN_PORT  = { audio:{L:'AUDIO_left', R:'AUDIO_right'}, ... };
const OUT_PORT = { escape:{L:'DNp01_left', R:'DNp01_right'}, ... };
```

实测确认（在 v4 真数据上跑出来的组规模）：

| 端口 | 左/右规模 | 说明 |
|---|---|---|
| `AUDIO_left/right` | 206 / 164 | 江氏器听觉亚类 JO-A\*/JO-B\* → 巨纤维 1 跳 |
| `JO_left/right` | 229 / 204 | 江氏器风/偏转亚类 → aDN1 梳理 |
| `TOUCH_left/right` | 150 / 155 | 头部刚毛 → DNa02 转向 |
| `DNp01_left/right` | 1 / 1 | 巨纤维逃逸（单神经元） |
| `DNa01`/`DNa02` | 1 / 1 | 转向 |
| `MDN` / `MN9` / `aDN1` | 2 / 1 / 1 | 后退 / 取食 / 梳理 |

⇒ 换 v4 → v5 → vS 只需**换一个 JSON 路径**，编排层**一行都不用改**。
（`FLYLAB` / `FLYDATA` 环境变量即可切换。）

### 1.3 但要说清：蘑菇体上来之后，能用的部分和不能用的部分

| | 现在（v4） | 加蘑菇体后（v5） |
|---|---|---|
| 现有端口 | `AUDIO`/`JO`/`TOUCH` → `DNp01`/`DNa`/`MDN`/`MN9`/`aDN1` | **完全不变**（逐位相同） |
| 新增 | — | `ORN_left/right`、`PAM_left/right`、`PPL1_left/right`（嗅觉 + 多巴胺） |
| 能驱动身体吗 | 能 | **蘑菇体本身仍然不能**（作者实测：有运动落点的 4 类 MBON **0 脉冲**；奖赏要外部直驱 PAM） |
| 实时余量 | 2.82× | **0.96×**（踩到实时线下） |

⇒ 所以"要不要上蘑菇体"**和"重新出位"无关**；真正的问题是**它现在还到不了马达**（这一条没变）。
门留着：加一个廉价 MOX 气味传感器 + 外部可塑层（`eco/` 那套），它才真正有用。

## 2. 问题二：多通道信息叠加怎么处理？

### 2.1 先把"叠加"这个词拆成两层（这是理解的关键）

用户说"肯定会有信息叠加" —— **对**。但叠加和压制**不在同一层**：

| 层 | 行为 | 我们能不能控制 |
|---|---|---|
| **输入层** | 多通道的脉冲电流在胞体**线性求和** | 能（就是给每个通道多大的 `setRate`） |
| **网络层** | 发放阈值 + 递归抑制 ⇒ 输出**互相压制**（这就是"注意力"） | **不干预**（这是连接组自身的性质） |
| **读出行** | 把发放率翻成动作 | 能（**唯一需要工程控制的地方**） |

之前实测的二维扫描（touch ≥100 把逃逸打到 0；audio ≥200 把转向打到 0）
**正是网络层的行为，不是 bug** —— 真实的果蝇也是这样"注意一件事"。

⇒ 所以"处理"不是去消除压制，而是**给输入分配权重**，让该赢的通道赢。

### 2.2 实测四种策略（在用户自己的 2 核实例上跑，原始输出见 `b_loop/stage1-loop-run-raw.txt`）

场景：音频由安静爬升到巨响（1.0 s / 1.8 s 两声峰值），触觉在 1.2–1.5 s、2.6–2.9 s
两次撞击（两者在 10 帧里重叠），JO 平稳小扰动。

| 策略 | 重叠帧 | 死区% | 逃逸% | 转向% | 判读 |
|---|---|---|---|---|---|
| **`sum` 优先级加权叠加** | 10 | **0** | **100** | 100 | ✅ 两路都保住，从不呆住 |
| `wta` 硬赢家通吃 | 10 | 0 | 100 | 100 | 可用，但切换生硬 |
| `soft_wta` 软赢家通吃（迟滞） | 10 | 0 | 100 | 100 | 可用；本轮听觉压没触觉的旧现象未复现 |
| `round_robin` 分时复用 | 10 | 0 | **0** | 100 | ❌ 逃逸整段丢失 |

> **转向列（全 100%）已失去区分力**：方向不再由脑给，重叠帧里 `lat = 0.7`
> 直接置位 `LEFT`，与仲裁策略无关。这张表现在只有**逃逸列**有信息量。

优先级设定（按果蝇行为学）：**逃逸(AUDIO) > 避障/转向(TOUCH) > 梳理(JO)**，
即 `audio 1.00 / touch 0.85 / jo 0.45`。

### 2.3 结论：默认用"优先级加权叠加"，并加一个死区看门狗

- **默认 `sum`**：既尊重"信息叠加"的生物事实，又不牺牲任何一路动作。
- **`soft_wta` 作为备选**：需要"注意力很强、只看一件事"的演示时用。
- **`round_robin` 淘汰**（逃逸整段丢失）。
- **兜底：死区看门狗 —— 已实现，见 §2.4。**

策略是可插拔的（`stage1_loop.js` 顶部 `ARBITERS` 表 + `--strategy` 开关），
换策略不用改一行别的代码。

### 2.4 死区看门狗：第一版错了，第二版才对（**这条最值得记**）

**它防什么**：`sum` 在"两路都强"时理论上仍可能落入死区。二维网格
（audio ∈ {0.30,0.40,0.50} × touch ∈ {0.25,0.35,0.45}，每格 2.0 s）实测：
**9 个格全部 100% 死区**（无看门狗时）。

**第一版（× 失败）**：连续 8 帧全静且输入 > 0.20 → 把**最强通道 ×2.0**，持 16 帧。
实测 **9 格一个都没救活**（唤醒 3 次，死区仍 100%）。

**为什么失败**：死区不是"驱动太弱"，是**跨通道交叉抑制**。
§2.2 的二维表就是证据：`AUDIO 300` 单独 → `DNp01 155`；`TOUCH` 一加入（哪怕 100）
→ 掉到 80；两者都 300 → 只剩 5。**另一条通道还在原位压它，放大自己没用。**

**第二版（✓ 生效）**：
1. **唤醒期间临时切「硬 WTA」** —— 其余通道**压到 0**，只留被唤醒的通道，再 ×2.0（持 16 帧）。
2. **唤醒通道的选择**：优先**最高行为优先级**且输入过阈值者（`audio > touch > jo`），
   都不过则退回"最大驱动"。
   —— 这条也踩过坑：`audio 0.30 × touch 0.45` 那格 touch 更"大"，用"最大驱动"会去唤醒
   `touch`，而 **v4 里 TOUCH 单独出不了任何行为**，等于没唤醒（该格旧规则仍 100% 死区）。

**实测结果**：**9/9 救活**（死区 100% → 45–50%；余下的是"唤醒 16 帧 / 静默 8 帧"的正常轮转）。
在**真机回放**（安静房间，输入 0.027 < 0.20）上触发 **0 次** —— 该有行为就有、真没刺激就不乱动。

**一句话**：**唤醒 = 注意力收窄（压制别人），不是把音量调大。**
