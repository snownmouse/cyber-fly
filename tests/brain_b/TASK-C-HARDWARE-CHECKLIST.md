## 第 1 步：开机日志确认三段都跑通

```powershell
$PY='D:\ESP\espressif-tools\python_env\idf6.2_py3.11_env\Scripts\python.exe'
& $PY mosaico.py --workspace D:\ESP\esp-mosaico-vibe iris logs --timeout 60
```

按顺序应看到（**缺任何一段就先解决那一步，不要往下走**）：

| 顺序 | 日志片段 | 含义 | 缺了怎么办 |
|---|---|---|---|
| 1 | `fly_wifi: 连接目标 SSID=your-ssid 密码长度=8` | 配置读到了 | 密码长度=0 就是 Kconfig 没生效 |
| 2 | `fly_wifi: 已连接 your-ssid（… ms，… 次尝试）` | Wi-Fi 关联成功 | 热点没开/是 5 GHz/密码错（看 reason 码） |
| 3 | `fly_mic: 麦克风已打开：16000 Hz …` | codec 打开成功 | 查 `bsp_power_init()` 是否先跑（框架已调） |
| 4 | `fly_link: 下行接收已启动 -> 192.168.1.100:33333` | socket 开了 | 地址/端口写错 |

**顺序很重要**：Wi-Fi 一定在 socket 之前（改成先连后开），所以第 1 条不出现时
第 4 条也不会出现。

⚠️ **读日志注意**：`mosaico.py` 输出里中文是乱码（`源=云端` 显示成 `婧?浜戠鐗?`），
因为固件发的是 UTF-8 而 PowerShell 按 UTF-16 读。**数字部分不受影响**，
判断闭环看 `tx=` / `rx=` / `坏帧=` / `RTT=` 即可。

## 第 2 步：看 `on_stats` 的源标记

`on_stats` 每个周期打一行，关键字段是 `源=`：

| 看到 | 含义 | 下一步 |
|---|---|---|
| `源=云端` | **闭环成功** | 直接跳到第 4 步 |
| `源=启动中` | 还在连 Wi-Fi / 开 codec | 等 30 s 再看 |
| `源=未联网` | 没有 DHCP 租约 | 回第 1 步第 1 条 |
| `源=已发无回` | **Wi-Fi 通、socket 通、发得出去，但云端不回** | 见第 3 步 |
| `源=内置` | 编译期 `FLY_LINK_ENABLE=n` | 检查 Kconfig |

`tx` 必须持续增长（≈20/秒）。`rx` 增长 = 真的收到下行了。

## 第 3 步：只有 `已发无回` 才需要：对称 NAT 退路

反射式回发被对称 NAT 挡住时，云端**主动 push 永远到不了**，但板子**轮询取**
可以工作（NAT 映射本来就被自己的 20 Hz 上行包刷新着）。

代价：50 ms 轮询周期仍在 400 ms 延迟预算内，**且不需要改云端**。
（`stage1_loop.js` 加一个 `--latest` 模式：把最新 MPRC 缓存在内存里供板子来取。）

先确认是不是 NAT 的问题：查云端 `serve.log` 里有没有 `已处理 N 帧` 在涨。
- 云端帧数在涨、板端 rx=0 ⇒ 板子发得到、云端回不来 ⇒ **确实是 NAT 回程被丢**
- 云端帧数也是 0 ⇒ 云端根本没收到板子包 ⇒ 问题在板子到公网（运营商/防火墙）

## 第 4 步：闭环行为验收（关键）

`on_stats` 之外，还要看**行为是否随声音变**。云端日志（`/root/serve.log`）
每一帧都打 `aud → esc groom flags`，这是脑的真实读出。

放歌测试（用任务 A 存档里那首 Nirvana《Smells Like Teen Spirit》）：

| 期望 | 判据 |
|---|---|
| 静息 | `aud ≈ 0.05`，`esc` 接近 0，屏上基本不动 |
| 音乐起手 20 s | `esc` 明显上升（`MAPV=v6` 用 Δrms 起始 + 门限响度） |
| 整首 | 逃逸随响度单调上升；最响档应接近 100% |
| 屏上 | 惊跳环亮、AROUSAL 条上升、头部转向 |

**如果音乐响度够但屏上完全不动**，按这个顺序查：

1. `rx` 在涨吗？不在涨 → 回到第 2/3 步（链路问题）
2. `rx` 在涨、`flags` 有 `ESCAPE` 位吗？没有 → **脑没被驱动**，
   即上行的 `rms_dbfs` 不对。查 `fly_mic` 的频段值（`band_*` 不该三个相同）
3. `flags` 有但屏上不动 → **渲染问题**，看 `seq`/`crc_ok` 是否连续

## 第 5 步：转向（需要真的推动板子）

设计文档 §0.5：**方向不由脑给**，走上行帧 `accel[0]`（带符号侧向加速度）。
当前 `fly_link_build_mprb(..., accel_x=0.0f)` 是**占位**——板端 IMU 还没接。

所以**本轮不验收转向**。要接的话：
- `bsp_imu_start()` + 读 BMI270（地址 **0x69**，不是 0x68）
- 把有符号侧向加速度传给 `fly_link_build_mprb`
- 板端**加同一行快反射**：`lat> +0.25 → LEFT`、`turn = clamp(-lat,-1,1)`
- 首帧转换要 `vTaskDelay(100ms)`，且只统计非零样本（Task A 踩过：BMI270 首次
  转换前读回全 0，混进平均会把 |a| 拉低 0.59 g）
