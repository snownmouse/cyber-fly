# 任务 B 算力方案：在现有 2 核 4G 上跑**实时**果蝇脑

> 结论先行：**不需要升配，也不需要 GPU。** 在现役 Lighthouse 实例上真机实测，全脑稀疏 LIF
> 单线程即可达到 **111–185 steps/s**，而 dt=20 ms 的"生物实时"只需要 **50 steps/s**，裕度 **2.2–3.7x**。
> 原先判定"跑不动"的依据（flybrain 官方 README 的 24 线程数字）来自**实现层的低效**，不是硬件天花板。

- 实测日期：2026-10-06
- 实例：`lhins-0t9s177k`（ap-shanghai，`192.168.1.100`）2 vCPU **AMD EPYC 7K83 @2.0GHz** / 3.66 GB RAM / 56 GB 空闲盘 / Debian 12 / Python 3.11.2
- 软件栈：numpy 2.4.6 + scipy 1.17.1，**float32**，**单线程**（未用第二颗核，未用 numba）

---

## 一、真机实测：硬件天花板（与任何仿真包无关）

方法：直接构造与真实连接组同规模、同稀疏度的 CSR 稀疏矩阵，测一次完整
"稀疏矩阵×脉冲向量 + LIF 膜电位更新 + 阈值发放"的单步耗时。活跃神经元比例取 4%
（依据：果蝇脑任一时刻约 **96% 的神经元是静默的**，见 §四-3）。

| 网络 | 规模（神经元 / 非零连接） | 方法 | ms/步 | steps/s | dt=20 ms 实时裕度 |
|---|---|---|---|---|---|
| FlyWire v783（雌，Shiu 官方） | 138,639 / 14.97 M | 朴素 CSR 全量乘 | 15.56 | 64 | ✅ 1.29x |
| FlyWire v783 | 同上 | **事件驱动列聚集** | **5.41** | **185** | ✅✅ **3.70x** |
| MaleCNS v1.0（雄，flybrain） | 166,700 / 25.50 M | 朴素 CSR 全量乘 | 28.70 | 35 | ❌ 0.70x |
| MaleCNS v1.0 | 同上 | **事件驱动列聚集** | **8.99** | **111** | ✅✅ **2.22x** |

峰值常驻内存 **449 MB**（4 GB 里剩 2.9 GB 可用，余量充足）。
原始输出见同目录 `ceiling-test-result.txt`。

**关键点：两种网络的"事件驱动列聚集"都过线了，而且只用了 1 颗核。**

## 二、为什么"实时"这件事本身是可以谈判的

生物实时 = 仿真时间与墙上时间 1:1。而**步长 dt 是我们自己选的**：

```
所需 steps/s = 1 / dt          （dt 单位：秒）
实时成立条件 = 实测 steps/s ≥ 1 / dt
```

| dt（每个脑步代表的生物时间） | 实时所需 steps/s | 我们的余量（按 111 steps/s） |
|---|---|---|
| 5 ms（kick-the-fly 的基准） | 200 | 0.55x ❌ |
| **20 ms（推荐，= 我们 50 ms 控制帧的 1 步）** | **50** | **2.22x ✅** |
| 40 ms | 25 | 4.4x ✅ |

我们现有的控制环就是 **20 Hz（50 ms 一帧）**，所以 **dt=20 ms 是天然对齐点**：
一帧 = 一个脑步 = 20 ms 生物时间 → 闭环在生物时间上是"真的实时"。

> 这是整件事的枢纽：**不是"让脑追上墙钟"，而是"让墙钟跟着脑的 dt 走"。**
> 只有当我们把 dt 压到 5 ms 以下（追求更细的积分精度）时才真的需要 GPU —— 而我们不需要。

## 三、三条可行路线（按推荐度排序）

### 路线 1（推荐）**官方 FlyWire v783 连接组 + 自研事件驱动 LIF**
- 数据：`philshiu/Drosophila_brain_model` 的 `Completeness_783.csv`(3.3 MB) + `Connectivity_783.parquet`(**101 MB**)
  —— 138,639 神经元 / 15,091,983 连接（pre、post、突触数、兴奋/抑制），**含神经递质极性预测**。
- 代码：我们只取它的**数据与极性规则**，执行层换成自己的 scipy/numba CSR 步进器。
- 实测：**185 steps/s 单线程**（1.29x → 3.70x 实时）。
- 优点：数据有 Nature 2024 背书，预测对光遗传实验的命中率 **164 项里 91%**；下载量只有 flybrain 的 1/3；
  连接数是 MaleCNS 的 59%。
- 代价：需要用复现里的权重规则自己搭步进器（不直接复用它的 Brian2 图）。

### 路线 2 **flybrain（MaleCNS，pip 装，最省事）**
- `pip install flybrain` → `FlyBrain(device="cpu")`，`dt` 可配；自带视觉前端、readout 工具链。
- 但它的 CPU 实现瓶颈在 Python/逐神经元开销：官方自述 **8.9–15 ms/步（24 线程）**。
  在我们 2 核上大概率落在 **0.3–1.0x** 实时（已装好待实测，见 §五）。
- 补救：不用它的 `step()`，改用它的 `weights.npz`（205 MB，同款 CSR）跑我们自己的步进器 —— 那就退化成路线 1 的做法。
- 另外：**它没有"只跑子集"的开关**（`brain.cells()` 只选刺激/读出群体，不缩网络）。

### 路线 3（保底，几乎不可能失败）**幼虫全脑**
- `Winding et al. 2023, Science` 的 **2,952 神经元 / 110,677 连接对 / 352,611 突触**。
- 第三方在 4 核 Xeon 云机上实测 **3,137（NumPy）– 3,986（numba）steps/s**，即 **15.7–19.9x 实时**（dt=5 ms 口径）。
- 我们这台更慢，保守折半仍有 **7–10x** —— 用 dt=5 ms 都能实时。
- 缺点（须如实说）：这是**幼虫**不是成虫；数据源**没有递质极性**（兴奋/抑制靠猜），
  猜错会让网络静息就自发放电（约 60 Hz）；只能 headless 跑。

## 四、支撑这套判断的四条外部证据

1. **Shiu et al., Nature 634:210–219 (2024)** —— 首个果蝇**全脑** LIF 计算模型（138.6k 神经元 / 15.09M 连接，Brian2）。
   官方 repo 的 config 里有 `'n_proc': -1  # number of CPU cores (-1: use all)`，**它是多核并行的**。
   第三方实测：Mac mini M4（10 核，纯 CPU）上"官方糖味样例 30 次 × 1 秒脑时间"共 **33 秒**。
   ⚠️ 该 repo 未在 README 说明 `dt`，而 33 s 这个数字的分母（是否已按 10 核展开）也无法从文档确认 ——
   这正是我坚持在真机上自己测的原因。
2. **Eon Systems 具身全脑（2026-03）** —— 把 Shiu 的 LIF 全脑接进 `NeuroMechFly v2` + MuJoCo（87 个独立关节），
   **脑↔身体同步回路 15 ms 一次**，无脚本、无训练、无奖励，涌现出走/理毛/逃逸/觅食行为。
   说明"全脑 + 真实身体 + 闭环"这条路已经被证明走得通。
3. **稀疏性是最大红利** —— 果蝇脑任一时刻约 **96% 的神经元静默**。
   我们的列聚集方法只处理"已发放神经元的入边"（实测 3.9% 活跃），
   理论上限就是把 25.5 M 条连接的工作量砍到约 1 M —— 这就是 28.7 ms 变成 8.99 ms 的来源。
   更极端的做法（**SparseProp**，事件驱动 + 二叉堆，复杂度 O(K·log N)）在 1 M 神经元 / 100 突触的网络上是
   "100 秒脑动力学 < 1 CPU 小时"，比传统事件驱动快 4 个数量级 —— 如果将来还需要更多裕度，这条路还没挖完。
4. **同规模对比** —— GeNN 论文报告"**100,000 神经元**可达真实时"（低端 GPU）；
   `SuperNeuroMAT` 声称稀疏模式在**普通笔记本**上跑到约 10 万神经元。
   两者都印证：**十几万神经元这个量级，本来就在 CPU/低端硬件的能力边界内。**

## 五、还剩的验证动作（低成本、按序做）

1. **跑通真实 flybrain 的 CPU 步进**，拿到它自身的 ms/步（已装好 flybrain 0.1.0，数据下载中）。
   → 若 ≤ 20 ms/步，路线 2 可以直接用，最省事。
2. **跑通 Shiu 官方 Brian2 样例**（需要 gcc 走 C++ codegen），量它的原生 ms/步 与 dt。
   → 拿到 dt 才能判断它的"0.9x 实时"到底是真是假。
3. **第二颗核 + numba parallel** 对照测试，确认余量能否再翻 1.5–1.9x（目前只用了 1 颗核）。
4. 定 **dt 的最终取值**（20 ms 起步，必要时退到 40 ms），并验证行为输出在粗 dt 下是否仍稳定。

### ⚠️ 已实测到的操作性阻塞：**数据源在国内服务器上不可用**

在本实例上实测：

| 目标 | 结果 |
|---|---|
| PyPI（`pip install flybrain` 及其 numpy/scipy/numba） | **约 80 MB/s**，秒下 |
| `flybrain download` ← `storage.googleapis.com`（260 MB） | **约 20 KB/s** → 全量需 **~4 小时** |

`brain.npz.part` 从 1 MiB 长到 7 MiB 用了约 6 分钟。**不是服务器带宽问题，是 Google Cloud Storage
在这台机器上被限速/阻断。** 用 `pip` 装包没问题，但**拉数据集不行**。

对策（按顺序）：① 在本地机器（国际出口正常）下载数据集，再用 base64 分块推送到服务器（每块 <1600 字符）；
② 找国内镜像/代理；③ 若都不可行，则把"脑"整体放在能直连数据源的那一侧。
Shiu 的数据（104 MB）在 GitHub，同样建议本地下载后推送。

## 六、真正的瓶颈不在算力，在延迟

任务 A 已实测：**RTT min 50.1 / avg 66.0 / max 100.4 ms，抖动 23.2 ms**。
加上 50 ms 特征窗口，端到端闭环地板 ≈ **130–180 ms**。
这个数**再好的 CPU 也降不下来**（是网络 + 窗口决定）。
所以任务 B 的架构建议是**分层**：

- **板端快反射**（微秒级，几条神经元；逃逸回路 `<10 ms`）—— 处理碰撞/失衡这类必须快的事；
- **云端全脑**（20 Hz，dt=20 ms）—— 处理"该往哪走"这类可以慢一点的事。

这也和果蝇的真实结构一致：巨纤维逃逸回路本身就是**绕过中央脑**的快速通路。

## 七、一句话总结

原先"必须升配或放弃实时"的结论**不成立**。它建立在 flybrain 一个**实现层低效**的数字上。
换成"事件驱动稀疏步进 + dt=20 ms"这个组合，**现役 2 核实例单线程就有 2.2–3.7x 实时裕度**，
数据可以用 Nature 2024 背书的 FlyWire v783（仅 104 MB）。保底还有幼虫全脑（7–10x 裕度）。
